# Map

Top level only. Most of the repo is Markdown prompts (skills and agents); the code that runs as a program
is listed below.

## Code folders

- `plugins/dev-kit/skills`, `plugins/dev-kit/agents` - the process as Markdown: skills and generic agents (one file per agent type).
- `plugins/dev-kit/scripts` - Python: `check_docs.py` checks a project's docs (every epic and feature has its sections, links, anchors and "Built in" paths resolve), finds the feature that owns a code file, lists open tasks and defects and the base docs files a project lacks; `check_tests.py` is the tests check; `run_app.py` starts and stops a project's app from the commands in its profile; `sessions.py`, `migrations.py`, `hard_bans.py` serve the project lead; `docs_weekly.py` starts the weekly docs session and keeps its state; `spend_client.py` runs the `spend-kit` command for `sessions.py` (a process, never an import).
- `plugins/rules-kit/scripts` - Python of the retro (the plugin about rules): `retro.py` scans the transcripts, sorts the findings into one folder per rule set, serves the retro session and writes the run file the docs hook reads; `subscriptions.py` reads the `rules-subscription.md` of each rule set (plugins, the owner's global rules, projects) and says which set owns a file; `parts.py` splits a transcript into parts by the skill, agent or hook at work and names their candidate sets; `talk.py` checks every reply to the owner against the talk rules (dashes, length, language, «так»/«ні» first); `packets.py` marks the parts with a sign and writes their packets for the part reader; `fixes.py` is the fix loop on the item files (2-week expiry, the weekly cap counted from the done list, replay packets, the clean-start check, own-files commit and restore of the owner's global folder, a revert only in a worktree, the fix record, the post-change check, `git revert`, revert requests, the done list, the spend cap); `rules_dir.py` is its data folder (`rules-kit` under the user's .claude folder) and the one-time copy from the old dev-kit retro folder; `folder_naming.py`, `claude_path.py` and `spend_client.py` are its own copies of the project folder name, the `claude` finder and the `spend-kit` runner (no plugin imports another's code).
- `plugins/rules-kit/skills`, `plugins/rules-kit/agents` - the `retro` and `edit-rules` skills, the `rule-reviewer` agent, the `part-reader` agent (haiku; names the rule line behind one part packet), the `approver` agent (opus; approves or rejects one retro fix in place of the owner) and the `replayer` agent (sonnet; says whether a fix covers a past problem part or breaks a good one).
- `plugins/*/rules-subscription.md` - the subscription of each plugin as a rule set (its files and their types, signs, what the retro may change itself, who reviews it and how a change lands); `plugins/rules-kit/templates/global-rules-subscription.md` is the template of the owner's global set, which the retro writes into the user's .claude folder on its first run.
- `plugins/rules-kit/bin`, `plugins/rules-kit/hooks` - the command `rules-kit` on the Bash tool PATH, and the retro hooks `retro-start.py` and `retro-end.py` (see Processes).
- `plugins/dev-kit/bin` - the commands on the Bash tool PATH while dev-kit is enabled: `dev-kit-check-docs`, `dev-kit-check-tests`, `dev-kit-app`, `dev-kit-sessions`, `dev-kit-migrations`, `dev-kit-docs`, `dev-kit-bans`.
- `plugins/spend-kit/scripts` - Python of everything about Claude spend: `spend.py` counts token units from the transcripts (`session`, `write-session`, `stats` with its never-cut `weekly.jsonl`, `critical`, `calibrate`, `scan`, `findings`, `units`, the SessionEnd `hook-end`) and fits the weekly limit; `statusline.py` is the status line that shows the weekly use and logs it for that fit; `limit_notices.py` gives from that log the Pult watcher's limit notices to the leads; `api_client.py` is the shared Claude API client that logs and reconciles spend, with its price table `plugins/spend-kit/api-prices.json`; `spend_dir.py` is the data folder and the one-time move of files from dev-kit's folder.
- `plugins/spend-kit/bin` - the commands on the Bash tool PATH while spend-kit is enabled: `spend-kit`, `spend-kit-statusline`, `spend-kit-api`.
- `plugins/spend-kit/hooks` - the SessionEnd hook `session-end.py` that starts the writing of the ended session's spend file.
- `plugins/dev-kit/hooks` - the hook that lets a project launch only its own agents, the hook that stops the known Windows shell traps, the hook that refuses long foreground commands, and the hook that tells an owner-started session the lead watches it ([hooks](hooks.md)), and the hook `docs-start.py` that starts the weekly docs session (see Processes).
- `plugins/dev-kit/slots.md`, `plugins/dev-kit/migrations.md` - the process steps (slots) and the changes every project must make after an update.
- `plugins/web-kit` - browser checks: skills and agents, `slots.md`, `browser-checks.md`, `.mcp.json` (the headless browser server, Playwright MCP, for sessions without the in-app browser); `scripts` holds `build-mockups.mjs` (mockup pages from JSON specs) and `capture.mjs` (headless full-resolution screenshots), `pair.mjs` (a mockup and its built screen side by side) and `default-mockups.css`; `bin` holds `web-kit-mockups`, `web-kit-shot` and `web-kit-pair`.
- `plugins/unity-kit` - Unity: skills and agent, `slots.md`; `scripts` holds `user_check.py` (plays a recipe in the editor and writes a report) and `frames_to_gif.py` (cuts and crops frames into a GIF); `bin` holds `unity-kit-user-check` and `unity-kit-gif`.
- `plugins/pult/scripts` - PowerShell and Python of the hub: start, stop, watch and restart of the leads, the status page, the session list.
- `plugins/pult/hooks`, `plugins/pult/rules` - the SessionStart hook and the hub rules it adds in the home folder.
- `.claude-plugin`, `plugins/dev-kit/.claude-plugin`, `plugins/web-kit/.claude-plugin`, `plugins/unity-kit/.claude-plugin`, `plugins/pult/.claude-plugin`, `plugins/spend-kit/.claude-plugin`, `plugins/rules-kit/.claude-plugin` - the marketplace and plugin manifests.
- `releases.json` in each plugin folder (dev-kit, pult, web-kit, unity-kit, rules-kit, spend-kit) - the critical or routine mark (and the optional `clean` flag) of each release of that plugin, read by the Pult watcher (it asks `sessions.py release --file` per changed plugin; rules-kit and spend-kit count for every lead, web-kit and unity-kit for the projects that enable them).
- `tools/enable-rules-spend-kit.py` - run once after the merge: enables spend-kit and rules-kit in the user's settings and points the status line at spend-kit (it backs the file up first).
- `tools/lint.py` - checks this repo: plugin manifests, skill and agent front matter, slot tables, hook config, the `rules-subscription.md` of every plugin, project profiles ([repo checks](repo-checks.md)).
- `tools/tests` - the tests of the scripts and hooks.
- `.githooks/pre-commit`, `.github/workflows/ci.yml` - the checks before a commit and in CI.

## Processes

- The Pult watcher (`plugins/pult/scripts/watch-servers.ps1`, started at logon) checks the leads every minute,
  runs `dev-kit-sessions check` for each lead and wakes the leads and Pult by a cross-session message (a one-shot
  `claude -p`) only on an event; it also moves a lead that saved a handoff to a fresh context (a resume with `/clear`, or a fresh session as the fallback).
- The Remote Control server "Pult", with cwd = the home folder, serves the phone; it passes the owner's requests to
  a lead by `plugins/pult/scripts/send-to-lead.ps1`, the same one-shot sender as the watcher's (`send-lib.ps1`).
- The session watcher (`dev-kit-sessions watch`) runs in the background only of a project lead on dev-kit before 0.1.78.
- The spend file of an ended session is written by spend-kit's SessionEnd hook; the retro takes its token findings by running `spend-kit findings`.
- The retro scan runs from rules-kit's SessionEnd hook (one transcript) and SessionStart hook (the full pass once a day), which also starts a background «Retro: <project>» session in a project with a lead. A dev-kit SessionStart hook starts, once a week, a «Docs: <project>» docs session, after reading the retro's run file in the rules-kit data folder.
- `dev-kit-app start` queues a project's app start between worktrees with a lock.

## Data stores

- `.claude/dev-kit.md` in every project - its profile ([project profile](project-profile.md)).
- The Pult state folder (pult under the user's .claude folder): logs (`servers.log`), `lead-versions.json` (with the day a lead first fell behind), the hold file, `status.html`, the wake files (`wake-pending.json`: messages not delivered yet; `wake-state.json`: size pushes and last send per target; `size-state.json`: transcript offsets for the size log), `limit-notices.json` (the limit notices already sent).
- The dev-kit state folder of a project: the session registry, locks, `restart.json`, the delivered marks of `check` (`delivered.json`, `check-closed.json`, beside `limits.json` and `stale.json`), and the weekly docs session's `docs.json` (`docs_started`, `docs_done`) with its `docs-items` folder.
- The rules-kit data folder (`rules-kit` under the user's .claude folder; the retro's files it took over from the old retro folder of dev-kit are copied once on the first run): the retro's global `state.json`, `notes.md` and scan logs, one folder per rule set (in `sets`: `new`, `seen`, `items`), one state folder per project (`state.json`), the part packets of `rules-kit parts` and `rules-kit replay` (`packets`), the done list `done.jsonl` that Pult's «статус» shows, revert requests (`requests`), and `runs/<project folder>.json`, the retro's run file that the dev-kit docs hook reads (never imported).
- The API spend log (`api-calls.jsonl` in the spend-kit folder of the user's .claude folder, beside `credits.md`, both copied once from the old dev-kit folder; other projects' programs still append to the old path, so the client reads both; its client `spend-kit-api` is in spend-kit): one line per paid Claude API call from every project ([log and reconcile API spend](../features/log-and-reconcile-api-spend.md); the line format: [API spend](api-spend.md)).
- The spend-kit data folder (`spend-kit` under the user's .claude folder; files it took over from the dev-kit folder are copied once on first use): `usage-log.jsonl`, one line per change of the weekly subscription per cent, written by `spend-kit-statusline`; `state.json`, the transcript offsets, per-day units, the weekly limit fit that `spend-kit` makes from the log, and the critical problems shown; `sessions/<session id>.json`, one spend file per ended session (read by other plugins, never imported). The Pult watcher's limit notices read the log (`limit_notices.py`).
